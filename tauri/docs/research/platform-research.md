# Glyph platform research: hardware-button voice capture on Android and iOS

Reference notes for the design panel. Everything below was read from primary sources on 2026-09-11 (AOSP source on android.googlesource.com, developer.android.com, Apple's documentation JSON, the crates in `~/.cargo/registry`, and AttackFM's checked-in `src-tauri/gen`). Web content is treated as data; where a fact could not be verified it is marked **verify**. Sibling notes: `mobile-shell.md` (the Tauri shell recipe), `scaffold.md` (the file plan). This document covers only the capture feature.

## 1. Android: becoming the digital assistant

### 1.1 The role, from `roles.xml`
`android.app.role.ASSISTANT` (PermissionController `res/xml/roles.xml`): `behavior="AssistantRoleBehavior"`, `defaultHolders="config_defaultAssistant"`, `exclusive="true"`, `exclusivity="user"`, `fallBackToDefaultHolder="true"`, `showNone="true"`, `overrideUserWhenGranting="true"`, **`requestable="false"`**. Consequences: one assistant per user (Glyph replaces Gemini/Bixby while it holds the role), "None" is offered, and `RoleManager.createRequestRoleIntent(ROLE_ASSISTANT)` shows nothing (confirmed independently by T. Künneth's dev.to write-up). The onboarding path is `startActivity(Intent(Settings.ACTION_VOICE_INPUT_SETTINGS))` (the "Digital assistant app" picker: Settings > Apps > Default apps > Digital assistant app) and `RoleManager.isRoleHeld(RoleManager.ROLE_ASSISTANT)` / `isRoleAvailable` to read state. The role also grants SMS/call-log permission sets to holders that declare them; Glyph must not declare them.

### 1.2 What qualifies (`AssistantRoleBehavior.java`, role-controller)
Either of:
1. A service found by `Intent(VoiceInteractionService.SERVICE_INTERFACE)` (`"android.service.voice.VoiceInteractionService"`) whose `permission` is `android.permission.BIND_VOICE_INTERACTION`, whose meta-data `android.voice_interaction` XML has `sessionService`, `recognitionService` **and** `supportsAssist="true"` (all three; `VoiceInteractionServiceInfo` parse errors are literally `"No sessionService specified"`, `"No recognitionService specified"`, `"Service does not require permission android.permission.BIND_VOICE_INTERACTION"`).
2. An **exported** activity matching `Intent(Intent.ACTION_ASSIST)` with `MATCH_DEFAULT_ONLY` (so `<category android:name="android.intent.category.DEFAULT"/>` is required).

Not available in work profiles (`isAvailableAsUser` rejects profiles). No automotive/TV exclusion in that file.

### 1.3 Manifest shape (AOSP voice-interaction guide, verbatim attribute names)
```xml
<uses-permission android:name="android.permission.RECORD_AUDIO"/>
<service android:name=".capture.GlyphInteractionService"
    android:permission="android.permission.BIND_VOICE_INTERACTION"
    android:process=":capture" android:exported="true">
  <meta-data android:name="android.voice_interaction"
             android:resource="@xml/voice_interaction_service"/>
  <intent-filter><action android:name="android.service.voice.VoiceInteractionService"/></intent-filter>
</service>
<service android:name=".capture.GlyphSessionService"
    android:permission="android.permission.BIND_VOICE_INTERACTION" android:process=":capture"/>
<service android:name=".capture.GlyphRecognitionService"
    android:permission="android.permission.BIND_VOICE_INTERACTION" android:process=":capture">
  <intent-filter><action android:name="android.speech.RecognitionService"/></intent-filter>
  <meta-data android:name="android.speech" android:resource="@xml/recognition_service"/>
</service>
```
`res/xml/voice_interaction_service.xml`: `<voice-interaction-service android:sessionService=".capture.GlyphSessionService" android:recognitionService=".capture.GlyphRecognitionService" android:settingsActivity="..." android:supportsAssist="true" android:supportsLaunchVoiceAssistFromKeyguard="true" android:supportsLocalInteraction="false"/>`. The `RecognitionService` can be a stub that reports `ERROR_RECOGNIZER_BUSY`; it only has to exist. Optional attributes parsed: `hotwordDetectionService`, `visualQueryDetectionService` (unused).

### 1.4 What invokes it (Android 12–16, verified in AOSP `main`)
- **Pixel long-press power**: Settings > System > Gestures > Press & hold power button > "Digital assistant" (vs "Power menu"); unchanged through Android 16 per 2026 guides. `PhoneWindowManager.powerLongPress()` case `LONG_PRESS_POWER_ASSISTANT` (= 5, from `Settings.Global.POWER_BUTTON_LONG_PRESS` / `config_longPressOnPowerBehavior`) does `performHapticFeedback(HapticFeedbackConstants.ASSISTANT_BUTTON, "Power - Long Press - Go To Assistant")` then `launchAssistAction(null, INVALID_INPUT_DEVICE_ID, eventTime, AssistUtils.INVOCATION_TYPE_POWER_BUTTON_LONG_PRESS)`. The OS supplies the haptic; Glyph's overlay should not add a second one on open.
- **Samsung One UI 7+** (S25, 2025-02-17; S26 support page 2026-06-16): Settings > Advanced features > Side button > Press and hold > "Open your preferred digital assistant (Gemini, Perplexity, etc.)" / Bixby / Power off menu. The list is the assistant-role holders. Double press = "Open app" (launcher activity only).
- **Corner swipe** (gesture navigation, Settings > System > Gestures > System navigation > "Swipe to invoke assistant", Android 12+) and **home-button long press** (3-button nav) reach the same role holder.
- SystemUI `AssistManager.startAssist(Bundle)`: refuses only in `LOCK_TASK_MODE_LOCKED`; adds `INVOCATION_PHONE_STATE_KEY` and `INVOCATION_TIME_MS_KEY`; then `isService = assistComponent.equals(getVoiceInteractorComponentName())`. Service path: `mAssistUtils.showSessionForActiveService(args, VoiceInteractionSession.SHOW_SOURCE_ASSIST_GESTURE, attributionTag, null, null)`. Activity path: `searchManager.getAssistIntent(structureEnabled)`, `setComponent`, `putExtras(args)`, `FLAG_ACTIVITY_NEW_TASK`, `startActivityAsUser`.
- `AssistUtils.INVOCATION_TYPE_KEY = "invocation_type"`: GESTURE 1, PHYSICAL_GESTURE 2, VOICE 3, QUICK_SEARCH_BAR 4, HOME_BUTTON_LONG_PRESS 5, POWER_BUTTON_LONG_PRESS 6, ASSIST_BUTTON 7, NAV_HANDLE_LONG_PRESS 8. Read it in `onShow(args, flags)` to label the capture ("from side key").
- **Volume-key long press in the background: not feasible** without an `AccessibilityService` (Play-restricted). Media-button sessions only see keys while the app plays media. Dropped.

### 1.5 Overlay, lock screen, recording
- `VoiceInteractionSession` creates its window as `TYPE_VOICE_INTERACTION`, `Gravity.BOTTOM`, flags `FLAG_HARDWARE_ACCELERATED | FLAG_LAYOUT_IN_SCREEN | FLAG_LAYOUT_INSET_DECOR`; UI via `onCreateContentView()`, `setTheme(int)` before `onCreate`, `setUiEnabled(bool)`, `hide()`, `finish()`. `WindowManagerPolicy.getWindowLayerFromTypeLw`: `TYPE_VOICE_INTERACTION` = layer 21 with the comment "voice interaction layer should show above the lock screen" (keyguard dialog = 19). So a VIS overlay is visible on the locked phone; an `ACTION_ASSIST` activity instead needs `android:showWhenLocked="true"` + `android:turnScreenOn="true"` (API 27) or the user unlocks first (**verify** the exact power-long-press-while-locked branch in `PhoneWindowManager.launchAssistAction` on a device; the fetch truncated).
- Process priority: the system binds the chosen VIS with `BIND_AUTO_CREATE | BIND_FOREGROUND_SERVICE | BIND_INCLUDE_CAPABILITIES | BIND_ALLOW_BACKGROUND_ACTIVITY_STARTS` (`VoiceInteractionManagerServiceImpl.startLocked`) and, while a session is shown, the session service with `BIND_TREAT_LIKE_ACTIVITY | BIND_SCHEDULE_LIKE_TOP_APP | BIND_TREAT_LIKE_VISIBLE_FOREGROUND_SERVICE` (`VoiceInteractionSessionConnection.showLocked`). Javadoc: "The current VoiceInteractionService that has been selected by the user is kept always running by the system".
- Microphone: `RECORD_AUDIO` must already be granted (runtime prompt inside the app's onboarding). With the session shown, `AudioRecord` in `onShow` is a foreground-capability record. To keep recording after `hide()`, the Android 14+ while-in-use exemption list explicitly includes "The service starts by an app which provides the VoiceInteractionService", so a `foregroundServiceType="microphone"` service (`FOREGROUND_SERVICE_MICROPHONE` + `RECORD_AUDIO`) may be started from that process. Transcription after the mic stops fits `shortService` (no type permission, ~3 min, `Service.onTimeout()` on 14+). `dataSync` is capped at 6 h/24 h on Android 15+; do not use it.
- Play: targetSdk 34+ apps declare every FGS type on the Play Console App content page with a description and a demo video; the microphone type's listed use is "Capture audio input, for example, voice commands for virtual assistant without saving, voice recording." No assistant-specific policy exists; Perplexity Assistant (Play, 2025-01) is precedent.

### 1.6 Complements
- **Quick Settings tile**: `<service android:permission="android.permission.BIND_QUICK_SETTINGS_TILE" android:exported="true">` with `<action android:name="android.service.quicksettings.action.QS_TILE"/>`, meta-data `android.service.quicksettings.ACTIVE_TILE`; in `onClick` use `startActivityAndCollapse(PendingIntent)` (API 34; the `Intent` overload is deprecated), `isLocked()`/`unlockAndRun(Runnable)` on the keyguard, `StatusBarManager.requestAddTileService(ComponentName, CharSequence, Icon, Executor, Consumer<Integer>)` (API 33) to offer adding it.
- **Static app shortcut**: `<meta-data android:name="android.app.shortcuts" android:resource="@xml/shortcuts"/>` on the launcher activity; `res/xml/shortcuts.xml` `<shortcut android:shortcutId="capture" android:shortcutShortLabel=... ><intent android:action="android.intent.action.VIEW" android:targetPackage=... android:targetClass=.../></shortcut>`; launchers show 4, `getMaxShortcutCountPerActivity()` up to 15.
- **Deep link `glyph://capture`**: `tauri-plugin-deep-link` `plugins.deep-link.mobile: [{ "scheme": ["glyph"] }]`; AttackFM's manifest comment records that `DeepLinkPlugin.kt` only forwards URLs whose scheme is in that list, and that the plugin rewrites its `<!-- DEEP LINK PLUGIN. AUTO-GENERATED -->` region on every build, so hand-written filters live outside it.

## 2. Tauri v2 mobile: plugin crate versus `gen/` edits

### 2.1 Plugin anatomy (from `tauri-plugin-haptics-2.3.2` and `tauri-plugin-2.6.3`)
`build.rs`: `tauri_plugin::Builder::new(COMMANDS).global_api_script_path("./api-iife.js").android_path("android").ios_path("ios").try_build()` (`COMMANDS: &[&str]`; `permissions/` autogenerated; rerun on `DEP_TAURI_ANDROID_LIBRARY_PATH`). `android/` is a Gradle library (`com.android.library`, `implementation(project(":tauri-android"))`, `jackson-databind`) with its own `AndroidManifest.xml` (haptics: `android.permission.VIBRATE`; notification: three `<receiver>`s plus `RECEIVE_BOOT_COMPLETED`/`WAKE_LOCK`/`POST_NOTIFICATIONS`) merged into the app by Gradle because `gen/android/tauri.settings.gradle` includes each plugin's `android/` dir from `~/.cargo/registry`. Kotlin: `@TauriPlugin class HapticsPlugin(private val activity: Activity): Plugin(activity)`, `@Command fun vibrate(invoke: Invoke)`, `@InvokeArg class HapticsOptions`, `invoke.resolve(JSObject)`; Rust: `api.register_android_plugin("app.tauri.haptics", "HapticsPlugin")`, `tauri::ios_plugin_binding!(init_plugin_haptics)`, `PluginHandle::run_mobile_plugin("impactFeedback", payload)`. Direction is Rust→Kotlin; the maintainer answer in tauri discussion #10695 is that Kotlin→Rust is "(currently) not 'unprompted'": only event listeners or the Channel API. `tauri plugin android init` / `tauri plugin ios init` scaffold the halves.

### 2.2 The house pattern (AttackFM, checked in)
`src-tauri/gen/android/app/src/main/AndroidManifest.xml` is hand-edited and tracked (`PlaybackService` with `foregroundServiceType="mediaPlayback|dataSync"`, a `NowPlayingWidget` receiver, a `FileProvider`, `RECORD_AUDIO`, `MANAGE_EXTERNAL_STORAGE`), with paragraph comments explaining each entry; Kotlin lives beside `MainActivity.kt` (`PlaybackService.kt`, `CastBridge.kt`, `NowPlayingWidget.kt`), never as a plugin crate. Kotlin↔page is `inner class NativeBridge` with `@JavascriptInterface` methods plus `wv.evaluateJavascript(...)`; there is no JNI in AttackFM. iOS: `gen/apple/Sources/app/{carplay.m,carplay.h,nearby.swift,airplay.swift,AudioEngine.swift,widgetPublish.swift}`, a `widget_iOS` app-extension target and `sdk:`/`package:` dependencies in the hand-edited `project.yml` (run `xcodegen generate` after edits), Rust↔ObjC via `extern "C"` (`afm_carplay_set_now_playing`, `#[no_mangle] pub extern "C" fn afm_carplay_remote`) and `build.rs` adding `-Wl,-undefined,dynamic_lookup` for the iOS cdylib. Glyph should follow this, not write a plugin crate.

### 2.3 Calling Rust from a Kotlin service with no webview
Generated `Rust.kt` already does `System.loadLibrary("app_lib")` and declares `@JvmStatic external fun create()` etc.; `tauri::android_binding!` (tauri 2.11.5 `src/lib.rs:132`) expands to `tao::android_binding!` which only generates `Java_<domain>_<pkg>_Rust_{create,start,stop,resume,pause,onActivityCreate,onActivityDestroy,onNewIntent,...}` plus `Java_app_tauri_plugin_PluginManager_{handlePluginResponse,sendChannelData}`; nothing runs at library-load time and no `JNI_OnLoad` is defined. So a Kotlin `Service` in the `:capture` process can `System.loadLibrary("app_lib")` and call its own `external fun transcribeAndSave(pcmPath: String): String` bound to `#[no_mangle] pub extern "system" fn Java_com_mattssoftware_glyph_capture_CaptureBridge_transcribeAndSave(mut env: JNIEnv, _cls: JClass, path: JString) -> jstring` (crate `jni`, already a transitive dependency via tao). `crate-type = ["staticlib","cdylib","rlib"]` keeps the export. The Rust store and whisper code must not touch `tauri::AppHandle`; they are plain modules the Tauri commands also call.

## 3. whisper.cpp on device

### 3.1 whisper-rs
`whisper-rs` 0.16.0 (crates.io, published 2026-03-12; 0.15.1 2025-09-10); development moved to `https://codeberg.org/tazz4843/whisper-rs`. `whisper-rs-sys` features (all off): `coreml`, `cuda`, `hipblas`, `openblas`, `metal`, `vulkan`, `openmp`, `intel-sycl`, `force-debug`; build-deps `cmake 0.1`, `bindgen 0.72` (needs libclang; `LIBCLANG_PATH`), `links = "whisper"`. `sys/build.rs` runs `cmake::Config` with `WHISPER_BUILD_TESTS=OFF`, `WHISPER_BUILD_EXAMPLES=OFF`, `BUILD_SHARED_LIBS=OFF`, `GGML_METAL=ON/OFF`, `GGML_METAL_EMBED_LIBRARY=ON`, `WHISPER_COREML=ON` (feature), links `framework=Accelerate` (+ `Foundation`, `Metal`, `MetalKit`, `CoreML`) on Apple, `c++_shared` on Android, and skips bindgen when `WHISPER_DONT_GENERATE_BINDINGS` is set (bundled bindings "may be out of date"). `FullParams`: `set_n_threads`, `set_language(Some("en"))`, `set_translate`, `set_no_context`, `set_single_segment`, `set_initial_prompt`, `set_no_timestamps`, `set_segment_callback_safe`, `set_progress_callback_safe`, `set_abort_callback_safe`, `enable_vad`, `set_vad_model_path`, `set_vad_params`, `set_temperature`, `set_suppress_blank`, `set_suppress_nst`, `set_max_len`; `SamplingStrategy::Greedy { best_of }` / `BeamSearch`.

### 3.2 Cross-compile facts and gotchas
- `tauri android build` uses cargo-mobile2, not cargo-ndk: `compile_lib` sets `ANDROID_NATIVE_API_LEVEL=<min_sdk>`, `TARGET_AR`, `TARGET_CC`, `TARGET_CXX` (NDK clang) and rustflags `-Clink-arg=-landroid -Clink-arg=-llog -Clink-arg=-lOpenSLES`; it sets **no** `CMAKE_TOOLCHAIN_FILE`.
- The `cmake` crate reads `CMAKE_TOOLCHAIN_FILE` from the environment (target-suffixed forms first), sets `CMAKE_SYSTEM_NAME=Android`/`CMAKE_SYSTEM_PROCESSOR`, and only treats the build as an NDK build (`uses_android_ndk()`) when both `ANDROID_ABI` and a toolchain file named `android.toolchain.cmake` are defined; otherwise it hands ggml the `cc`-crate compiler. Put `CMAKE_TOOLCHAIN_FILE=$NDK_HOME/build/cmake/android.toolchain.cmake`, `ANDROID_ABI=arm64-v8a`, `ANDROID_PLATFORM=android-24`, `GGML_NATIVE=OFF`, and `CMAKE_C_FLAGS=-march=armv8.2-a+fp16` (whisper.android's arm64 flag; `-O3`, `GGML_USE_CPU`) in `src-tauri/.cargo/config.toml [env]` scoped by target, or patch them into a fork of `sys/build.rs`. **Not built in this session; run as the first spike.**
- bindgen against the NDK sysroot needs `BINDGEN_EXTRA_CLANG_ARGS_aarch64_linux_android="--sysroot=... --target=aarch64-linux-android24"`, or set `WHISPER_DONT_GENERATE_BINDINGS=1`.
- `c++_shared` means `libapp_lib.so` will `NEED libc++_shared.so`; check with `readelf -d`, and copy it from the NDK sysroot into `jniLibs/arm64-v8a` (Gradle only packages it for its own native builds).
- Known upstream Android/aarch64 build issues (#2647 missing `ggml-aarch64.c`, #3026/#3051 `HWCAP_*` macros) are ggml-version specific; pin the whisper-rs version and vendor if needed.
- iOS: `metal` feature (shader embedded) and optionally `coreml` (encoder `.mlmodelc` downloaded separately, `ggml-base.en-encoder.mlmodelc.zip` 38 MB, ">3x faster" encoder); add `Accelerate.framework` and `CoreML.framework` to `project.yml` (`Metal`, `MetalKit` are already there in AttackFM). `libapp.a` is static, so no `dynamic_lookup` issue beyond the one AttackFM already handles.

### 3.3 Models, memory, speed
Sizes on `huggingface.co/ggerganov/whisper.cpp`: `ggml-tiny.en-q5_1.bin` 32.2 MB, `ggml-base.en-q5_1.bin` 59.7 MB, `ggml-small.en-q5_1.bin` 190 MB, `ggml-tiny.en.bin` 77.7 MB, `ggml-base.en.bin` 148 MB, `ggml-small.en.bin` 488 MB, `ggml-large-v3-turbo-q5_0.bin` 574 MB. whisper.cpp README memory (F16): tiny ~273 MB, base ~388 MB, small ~852 MB; q5_1 cuts weights ~3–4x, so expect roughly 200–250 MB resident for base.en-q5_1 (**verify** on device). Speed data points: iPhone 13 mini, base, 4 threads: encoder 1091 ms per 30 s window (2022, issue #89 / openai discussion #407, "about 1 s base, 3 s small"); Galaxy S24 Ultra, distil-small.en ggml, streaming 5 s chunks, ~2x real time (2024-03); Snapdragon 778G, tiny q8_0 118 ms and base q8_0 245 ms per 1 s chunk (mvpfactory, 2026-09-01); WhisperKit large-v3-turbo Core ML on iPhone 15 Pro ~7x real time. Rule of thumb for planning: base.en-q5_1 on a 2023+ flagship CPU transcribes a 60 s note in ~10–20 s, tiny.en in ~4–8 s; whisper.cpp recommends tiny/base on Android. Large models OOM on phones (reported even on S25).

### 3.4 Alternatives
- **sherpa-onnx** official Rust crate `sherpa-onnx` 1.13.8 (2026-09-11; Android/iOS/prebuilt libs); whisper `tiny.en`…`turbo`, `distil-*` with int8 exports, plus Zipformer/Moonshine/Parakeet; whisper there is non-streaming (30 s windows, chunk with its VAD; **verify** current limit). Fallback if whisper-rs will not cross-compile.
- **Android `SpeechRecognizer`**: `isOnDeviceRecognitionAvailable(Context)` / `createOnDeviceSpeechRecognizer(Context)` (API 31 from memory; page unfetchable), `checkRecognitionSupport(...)` / `triggerModelDownload(...)` (API 33); main thread only; default engine "is likely to stream audio to remote servers"; Google-dependent, no batch mode.
- **iOS**: `SFSpeechRecognizer` (`supportsOnDeviceRecognition`, `requiresOnDeviceRecognition`) and iOS 26 `SpeechTranscriber` (`isAvailable`, `supportedLocales`, `installedLocales`, `supportedLocale(equivalentTo:)`, `init(locale:preset:)`, `results` AsyncSequence; models via `AssetInventory`; `DictationTranscriber` fallback). Free, on-device, Apple-quality; the strongest reason not to ship whisper on iOS at all in v1.
- **OpenAI API** (developers.openai.com, 2026-09): "Files can be up to 25 MB", formats mp3/mp4/mpeg/mpga/m4a/wav/webm; models `gpt-transcribe`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`, `whisper-1`; ~$0.006/min (`whisper-1`, `gpt-4o-transcribe`), ~$0.003/min (`gpt-4o-mini-transcribe`).

## 4. iOS
- **Action button**: iPhone 15 Pro/Pro Max and every iPhone 16/17 model; Settings > Action Button offers Shortcut (any shortcut or App Shortcut) and, since iOS 18, Controls. App Shortcuts: a type adopting `AppShortcutsProvider` with `static var appShortcuts: [AppShortcut]` built from `AppShortcut(intent:phrases:shortTitle:systemImageName:)`; discovered at build time by the AppIntents metadata extractor, available on install, surfaced in Siri, Spotlight, Shortcuts and the Action button. `AppIntent` needs `static var title: LocalizedStringResource` and `func perform() async throws -> some IntentResult`. `openAppWhenRun` is deprecated in iOS 26 for `static var supportedModes: IntentModes` (`.background`, `.foreground(.immediate)`, `.foreground(.dynamic)`, `.foreground(.deferred)`, combinable; `continueInForeground(_:alwaysConfirm:)`), keep the old property for 16–18. Intents declared in the app target run in the app process.
- **Controls** (iOS 18): `ControlWidget` with `StaticControlConfiguration` and `ControlWidgetButton` in a widget extension, action an `AppIntent` conforming to `OpenIntent` to open the app; "Target Membership of the app intent to be set to both the app and the widget extension". Assignable to Control Center, Lock Screen and the Action button. AttackFM's `widget_iOS` target in `project.yml` is the template.
- **Background recording is impossible**: Apple forum thread 815725 ("Target is not foreground"): apps cannot initiate `AVAudioSession` recording from the background via an intent; `AudioRecordingIntent` (iOS 18+) only starts/stops an already-established session and requires a Live Activity. Therefore the iOS capture intent must foreground Glyph (`.foreground(.immediate)` / `openAppWhenRun = true`) and start recording on arrival; the Rust store is available because the whole Tauri app is running.
- **Back Tap**: Settings > Accessibility > Touch > Back Tap > Double/Triple Tap > any shortcut (iPhone 8+). Free with the same App Shortcut.
- Tauri wiring: `gen/apple/Sources/app/CaptureIntent.swift` (the app target already compiles Swift), `- sdk: AppIntents.framework` in `project.yml`, `perform()` calls `glyph_request_capture()` declared in `Sources/app/bindings/bindings.h`'s `extern "C"` block (AttackFM's `ffi::start_app()` pattern) which Rust implements with `#[no_mangle]` and turns into a Tauri event, or simply opens `glyph://capture`. `NSMicrophoneUsageDescription` already lives in `Info.ios.plist`. `xcodegen generate` after editing.

## 6. Recommended architecture
1. **Android capture lives in a `:capture` process** made of three Kotlin services in `gen/android/app/src/main/java/<pkg>/capture/`: `GlyphInteractionService` (VIS; overrides `onReady`, `onLaunchVoiceAssistFromKeyguard` → `showSession(args, SHOW_SOURCE_ASSIST_GESTURE)`), `GlyphSessionService`/`GlyphSession` (the overlay: a small Compose/View sheet at `Gravity.BOTTOM` with the level meter, elapsed time, Stop; starts `AudioRecord` 16 kHz mono PCM16 in `onShow`, reads `invocation_type`), and a stub `GlyphRecognitionService`. Stop (or 90 s cap) writes `<filesDir>/captures/<uuid>.wav`, starts a `shortService` FGS whose notification doubles as the save confirmation, and calls `CaptureBridge.transcribeAndSave(path)` on a worker thread.
2. **Rust owns storage and whisper** in a `glyph_core` module (no Tauri types): `rusqlite` (bundled) at `<data_dir>/glyph.sqlite` in WAL mode with `busy_timeout`, tables `notes(id, body, created_at, updated_at, source)` and `captures(id, note_id, audio_path, model, duration_ms, state)`; `transcribe(path, model) -> String` loads `ggml-base.en-q5_1.bin` lazily (`tiny.en-q5_1` when `ActivityManager.isLowRamDevice()` or under ~4 GB), `set_language(Some("en"))`, `enable_vad`, `set_n_threads(min(4, cores))`, then drops the context. Both the JNI export and the Tauri commands (`list_notes`, `save_note`, `capture_pending`) call it. The Android `:capture` process loads `libapp_lib.so` without ever running `tauri::Builder`.
3. **The webview learns on resume**: `MainActivity.onResume`/`onNewIntent` evaluates `window.__glyph?.refresh()` (AttackFM's `evaluateJavascript` pattern), and the page re-queries; no cross-process Tauri events needed.
4. **iOS**: `CaptureNoteIntent` (App Shortcut + Control), `supportedModes = .foreground(.immediate)`, `perform()` → `glyph_request_capture()`; the app foregrounds, records natively in Swift (`AVAudioEngine`, `UIBackgroundModes: audio` so a started capture survives the lock button), hands PCM to the same Rust `transcribe` (whisper-rs `metal`), or in v1 uses `SpeechTranscriber` on iOS 26 with whisper as the pre-26 path.
5. **Complements**: tile, static shortcut, `glyph://capture`, and an in-app mic button all funnel into one `startCapture(source)` entry so the transcript pipeline and haptics are identical.
6. **Models**: bundle nothing large; download `base.en-q5_1` (60 MB) on first run from HF with a SHA-256 check and keep `tiny.en-q5_1` (32 MB) in assets as the offline floor. Cloud Whisper is an opt-in setting.

## 7. Ranked risks and mitigations
1. **whisper-rs Android cross-compile** (cmake toolchain, bindgen sysroot, `libc++_shared.so`, ggml aarch64 build breaks): spike day one; env in `.cargo/config.toml`; `WHISPER_DONT_GENERATE_BINDINGS`; fall back to the `sherpa-onnx` crate or on-device `SpeechRecognizer`.
2. **Users must give up Gemini** and the role is not requestable: an onboarding card that opens `ACTION_VOICE_INPUT_SETTINGS`, shows role state with `isRoleHeld`, and offers the tile/shortcut path when they decline.
3. **Memory in an always-bound process**: separate `:capture` process, lazy model load/free, tiny.en floor, 90 s cap per capture, VAD.
4. **Lock-screen behaviour differs by OEM**: test matrix Pixel (16) + Galaxy (One UI 7/8); `supportsLaunchVoiceAssistFromKeyguard="true"`; never rely on an `ACTION_ASSIST` activity for locked capture.
5. **Play review of `FOREGROUND_SERVICE_MICROPHONE`**: record only while the overlay is up unless the user backgrounds mid-capture; provide the demo video; prominent disclosure before the `RECORD_AUDIO` prompt.
6. **iOS has no headless capture**: accept foreground-first; keep the intent → record latency under a second (start `AVAudioEngine` before the webview paints).
7. **Manifest merge fragility**: keep VIS/tile/shortcut entries outside the deep-link plugin's generated region and comment them in the house voice.
8. **Two processes writing SQLite**: WAL, `busy_timeout`, single short transactions, and a `refresh()` on activity resume.
9. **English-only `.en` models**: expose a language setting that switches to the multilingual `base-q5_1` file.
10. **Accuracy expectations**: tiny/base misspell names; show the transcript as an editable draft with the audio kept until the user saves.
