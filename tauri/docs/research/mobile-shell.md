## 2. Commands (already in `package.json`)

```

Never call `tauri ios build` bare: `ios-clean.mjs` deletes `gen/apple/build/{app_iOS.xcarchive,arm64,arm64-sim,x86_64-sim}`, `gen/apple/Externals`, `gen/apple/assets` and `dist`, because Tauri finishes an iOS build with `rename()` which fails `ENOTEMPTY` (os error 66) on the second build, `Externals/<arch>/{debug,release}/libapp.a` collide as "Multiple commands produce", and `gen/apple/assets` is never pruned so a stale `index.html` can ship.

## 3. Config files

`tauri.conf.json` (Glyph, keep): `build.devUrl` `http://localhost:5250`, `beforeDevCommand` `npm run dev`, `beforeBuildCommand` `npm run build`, window `label: "main"`, `"backgroundThrottling": "disabled"`, `"security": { "csp": null }`, `bundle.iOS.minimumSystemVersion: "15.0"`, `bundle.iOS.developmentTeam: "F6ZAL7ANAD"`. AttackFM also sets `"withGlobalTauri": true` (its boot loader reads `window.__TAURI__`); Glyph does not need it. `tauri.ios.conf.json` repeats the window with `backgroundThrottling: "disabled"` and `"bundle": { "externalBin": [] }`; `tauri.android.conf.json` is the same without throttling. Both use `"$schema": "./gen/schemas/mobile-schema.json"`.

`Info.ios.plist` is merged into the generated plist and is the ONLY place plist keys survive: `tauri ios build` regenerates `gen/apple/app_iOS/Info.plist` and drops manual keys. It carries `UIApplicationSceneManifest` with `UIApplicationSupportsMultipleScenes: true` and a `UIWindowSceneSessionRoleApplication` entry naming `TaoSceneDelegate` (iOS 26+ traps apps without scene adoption; fatal on the 27 runtime), `CFBundleURLTypes` with scheme `glyph`, `NSMicrophoneUsageDescription`, `ITSAppUsesNonExemptEncryption: false`, `LSApplicationCategoryType`. AttackFM adds `UISupportedInterfaceOrientations: [Portrait]` there too.

`capabilities/default.json`: `core:default`, the four `core:window:allow-*` (desktop title bar), `opener:default`, `haptics:allow-impact-feedback`, `haptics:allow-notification-feedback`, `haptics:allow-selection-feedback`. AttackFM adds `deep-link:default`, `notification:default`, `dialog:allow-open`, `fs:allow-mkdir`, `fs:allow-exists`, `fs:allow-*-read-recursive`/`write-recursive`. Glyph's store is Rust-owned, so no `fs:*` needed; add `deep-link:default` when the plugin lands. `src-tauri/.gitignore` is `/target` and `/gen/schemas`.

## 4. Cargo.toml and the tao patch

`[lib] name = "glyph_lib"`, `crate-type = ["staticlib", "cdylib", "rlib"]` (staticlib is what Xcode links; Android builds the cdylib). Desktop-only crates go under `[target.'cfg(not(any(target_os = "ios", target_os = "android")))'.dependencies]` (`tauri-plugin-decorum = "1"` does not build for mobile). iOS-only: `[target.'cfg(target_os = "ios")'.dependencies] objc2 = "0.6"` (AttackFM also pulls `objc2-foundation` for `NSURLIsExcludedFromBackupKey`, worth copying for the notes directory: `nobackup.rs`). Network crates must be `rustls` not `native-tls` (OpenSSL will not cross-compile for Android).

`[patch.crates-io] tao = { path = "vendor/tao" }`: tao 0.35.3 returns the `UISceneConfiguration` from `application:configurationForConnectingSceneSession:` without transferring ownership; release builds free it before UIKit reads it and segfault in `-[UIApplication _connectUISceneFromFBSScene:transitionContext:]` on iOS 26/27 devices while debug survives on autorelease luck. The vendor copy is pristine 0.35.3 plus the one-line 0.36.0 backport. Drop it once `tauri-runtime-wry` depends on tao >= 0.36.

## 5. lib.rs shape

`#[cfg_attr(mobile, tauri::mobile_entry_point)] pub fn run()`; `main.rs` calls `glyph_lib::run()`. Plugins in order: `tauri_plugin_opener::init()`, `tauri_plugin_haptics::init()`, later `tauri_plugin_deep_link::init()`; `#[cfg(desktop)] let builder = builder.plugin(tauri_plugin_decorum::init());`. In `setup`: AttackFM installs a panic hook writing `last-native-death.txt` into `app.path().app_data_dir()` (a Rust panic aborts silently on a phone; copy this), then `#[cfg(target_os = "ios")] ensure_key_window(&app.handle())` (asserts `makeKeyAndVisible` at 600 ms and 2200 ms; without it the keyboard never rises under the scene lifecycle: Apple QA1813). AttackFM keeps two `invoke_handler()` functions, `#[cfg(desktop)]` and `#[cfg(mobile)]`, so desktop-only modules never appear in a phone build; mobile-only native code lives in `#[cfg(target_os = "ios")] mod native { extern "C" { ... } }` seams with no-op fallbacks so the frontend calls unconditionally.

## 6. iOS post-init (`src-tauri/gen/apple`)

`tauri ios init` writes `project.yml` from its own template and leaves an existing one alone; a delete-and-reinit resets it. Hand edits (AttackFM's header lists them): `options.deploymentTarget.iOS: 15.0` (template hardcodes 14.0, which Xcode 26+ refuses: "supported deployment target versions is 15.0 to 27.0.x"; the CLI does NOT read `minimumSystemVersion`); under `targets.app_iOS.settings.base`: `DEVELOPMENT_TEAM: F6ZAL7ANAD`, `CODE_SIGN_STYLE: Automatic` (not propagated from `developmentTeam` either), `TARGETED_DEVICE_FAMILY: "1"`, `ENABLE_BITCODE: false`; the `Externals` source entry needs `buildPhase: none` or two arch dirs both holding `libapp.a` collide. After ANY edit run `xcodegen generate` in `gen/apple`; neither `ios init` nor `ios build` re-runs it.

Plugin Swift: `tauri-plugin` 2.6.3 links a plugin's `ios/` package at cargo time via `tauri_utils::build::link_apple_library` (swift-rs), copying `mobile/ios-api` to `<plugin>/.tauri/tauri-api`. AttackFM nevertheless found the Taptic Engine silently no-op and hand-vendored the package: `gen/apple/tauri-plugin-haptics/{Package.swift,Sources/HapticsPlugin.swift}` (copied from the crate's `ios/`, its `Package.swift` pointing at `../.tauri/tauri-api`), `gen/apple/.tauri/tauri-api` copied from `tauri-2.11.5/mobile/ios-api`, plus `packages: { tauri-plugin-haptics: { path: tauri-plugin-haptics } }` and `dependencies: - package: tauri-plugin-haptics` in `project.yml`. For Glyph: run `ios init` with the plugin already in `Cargo.toml`, grep `project.yml` for `tauri-plugin-haptics`, test on a device, and apply the vendoring only if impacts stay silent.

Tracked vs ignored (AttackFM `.gitignore`): ignore `gen/apple/build`, `Externals`, `app.xcodeproj`, `Pods`, `Podfile.lock`; Glyph also ignores `gen/apple/assets`. `project.yml`, `app_iOS/*.entitlements`, `Sources/app/*` stay tracked. Entitlements must be declared as `entitlements.properties` in `project.yml`; xcodegen rewrites the `.entitlements` file on every generate.

## 7. Android post-init (`src-tauri/gen/android`)

Generated and ignored: everything except `app/src/main/AndroidManifest.xml`, `app/build.gradle.kts` (carries release `signingConfigs` reading `keystore.properties`, which is ignored), `app/src/main/java/<pkg>/*.kt` except `generated/`, `res/values/**`, `res/values-sw600dp/**`, `res/xml/**`. `.gitignore` must use `src-tauri/gen/android/**` then `!` re-includes per directory level (git cannot re-include below an excluded directory).

`MainActivity.kt` extends the generated `TauriActivity` (which sets `handleBackNavigation = false`). AttackFM's shape: `onCreate` installs a `Thread.setDefaultUncaughtExceptionHandler` writing `last-uncaught-death.txt`, calls `enableEdgeToEdge()` BEFORE `super.onCreate`, then `applyOrientationLock()` (portrait when `R.bool.afm_rotate` is false; `values-sw600dp/bools.xml` flips it). `override fun onWebViewCreate(webView: WebView)` is the hook that exists once the page exists: wrap `webView.webViewClient` in a client whose `onRenderProcessGone` writes a note and calls `activity.recreate()` (default kills the app), `addJavascriptInterface(NativeBridge(), "AFMNative")`, and register `onBackPressedDispatcher.addCallback` that evaluates `window.__AFM_BACK__ ? window.__AFM_BACK__() : false` and calls `moveTaskToBack(true)` unless the result is `"true"`. Glyph: rename to `GlyphNative` / `__GLYPH_BACK__` and port `src/app/nav/systemBack.ts` (`onSystemBack(handler)`, `useSystemBack(active, close)`, handlers walked newest-first).

`res/values/themes.xml` (and `values-night`): `Theme.app` parent `Theme.MaterialComponents.DayNight.NoActionBar`, `android:navigationBarColor`/`statusBarColor` transparent, `android:enforceNavigationBarContrast false`, `android:windowBackground #0f0f10` (the same first-paint colour as `index.html`). `build.gradle.kts`: `compileSdk 36`, `minSdk 24`, `targetSdk 36`, `kotlinOptions.jvmTarget "1.8"`, AGP 8.11.0, Kotlin 1.9.25. `android.permission.VIBRATE` arrives by manifest merge from the haptics plugin's own `AndroidManifest.xml`; nothing to add.

Deep links: the `attackfm` scheme is NOT hand-written in the manifest. The plugin regenerates the `<!-- DEEP LINK PLUGIN. AUTO-GENERATED. DO NOT REMOVE. -->` block from `tauri.conf.json` `plugins.deep-link.mobile: [{ "scheme": ["glyph"] }]`, and its Kotlin half forwards only URLs matching that list, so a manifest-only scheme opens the app and goes nowhere. Frontend wiring is AttackFM's `initDeepLinks()`: `const mod = await import('@tauri-apps/plugin-deep-link'); (await mod.getCurrent())?.forEach(deliver); await mod.onOpenUrl((urls) => urls.forEach(deliver));` held in a tiny store because the URL can arrive before any React tree mounts.

## 8. Frontend modules to port

`src/app/core/tauri.ts`: `export function isTauri(): boolean { return typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window; }`, `tauriCall<T>(cmd, args)` returning `null` off Tauri or on any error, `safeUnlisten()` retrying once after 250 ms.

`src/app/core/platform.ts`: `isMobile` (UA `/Android|iPhone|iPod/`, `/iPad/`, or Macintosh UA plus any touch signal), `isIOS`, `isAndroid`, `isDesktopApp = isTauri() && !isMobile`; and the stamp, from module body not an effect: `document.documentElement.dataset.platform = isAndroid ? 'android' : isIOS ? 'ios' : 'desktop'` so `html[data-platform='android']` rules apply on first paint.

`src/app/core/haptics.ts`: `const nativeHaptics = isTauri() && isMobile`; lazy `import('@tauri-apps/plugin-haptics')`; `fireNativeHaptic(kind: HapticKind = 'light')` maps `selection` to `selectionFeedback()`, `medium`/`heavy` to `impactFeedback(kind)`, `success|warning|error` to `notificationFeedback(kind)`, else `impactFeedback('light')`, gated by `hapticsPref()` (localStorage key, default `isMobile`); `export const hapticsImpl = nativeHaptics ? fireNativeHaptic : undefined`; `hapticsAvailable()` gates the Settings row; `fireMicroTick()` is `impactFeedback('soft')`; `fireFelt(kind, at = performance.now())` enforces `FLOOR_MS = 28`; `installTapHaptics()` fires `selection` on pointerup within `TAP_SLOP_PX = 10` and `TAP_MAX_MS = 700` over a `TAPPABLE` selector, capture-phase, touch only; `useHapticsPref()` via `useSyncExternalStore`. Plugin API: `impactFeedback('light'|'medium'|'heavy'|'soft'|'rigid')`, `notificationFeedback('success'|'warning'|'error')`, `selectionFeedback()`, `vibrate(ms)`.

`src/app/ux/ratchet.ts`: `NOTCH_FAR = 24`, `NOTCH_NEAR = 9`, `TICK_FLOOR_MS = 28`; pure `notchWeight(p)` (`micro` < 0.45, `selection` < 0.8, else `light`), `notchSpacing(p)`, `nextNotch(travel, from, to, since)`; `makeRatchet(): Ratchet` with `feel(travel, from, to, nowMs)`, `arrive(weight = 'medium')` once per gesture, `reset()`. Pure so `ratchet.test.ts` can verify it with mocked haptics.

Provider: `<HapticsProvider enabled={false} impl={hapticsImpl}>` from `@glacier/react`. The kit's `HapticsProviderProps` are `enabled?: boolean` (default false) and `impl?: HapticFn`; `HapticKind = 'selection' | 'light' | 'medium' | 'heavy' | 'success' | 'warning' | 'error'`; `useHaptics()` returns the impl plus a feedback-bus emit. `enabled` only gates the kit's delegated pointerdown tick (which buzzed during scrolls, hence off) and its web engine; `impl` still reaches every kit surface.

Appearance: `AppearanceProvider` writes `data-theme` (`light`/`dark`, removed for system), `data-theme-preset`, `data-accent` (removed at default), `data-density` (removed at `comfortable`) on `document.documentElement`; tokens.css recognises `[data-density='compact'|'extra-compact'|'spacious'|'more-space']`, `[data-accent='teal'|'red'|'purple'|'green'|'graphite'|'amber']`, `[data-theme-preset='ember'|'dawn'|'boreal']`, `[data-font='plex'|'noto']`, `[data-mono='plex']`.

## 9. CSS shell

`index.html`: `<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no, viewport-fit=cover">` (no zoom on sub-16px inputs; `viewport-fit=cover` is what makes `env(safe-area-inset-*)` non-zero) and an inline `html { background: #0f0f10 } html[data-theme='light'] { background: #ffffff }` first paint. `app.css`: `--app-safe-top/bottom/left/right: env(safe-area-inset-*, 0px)` (AttackFM declares them on `.appWindow`, Glyph on `:root`, which is better: portalled sheets and toasts lose `.appWindow` vars and a bare `var(--app-safe-top)` poisons the whole `calc()`), `#root { height: 100vh; height: 100dvh }`, `html, body { overscroll-behavior: none; -webkit-text-size-adjust: 100% }` unconditionally (the `@supports (-webkit-touch-callout: none)` hack is false in Blink), `html { -webkit-touch-callout: none; -webkit-user-select: none; user-select: none; -webkit-tap-highlight-color: transparent }` with `input, textarea, select, [contenteditable], [contenteditable] * { -webkit-touch-callout: default; user-select: text }` restored (the editor lives here), `:focus:not(:focus-visible) { outline: none }`, `img { -webkit-user-drag: none }`, bottom chrome padded by `max(12px, env(safe-area-inset-bottom))`, and `html[data-platform='android'] ...` lifting bottom bars by the full inset (Android's gesture bar is a control surface; iPhone's indicator is draped over). AttackFM's `postcss.config.mjs` runs `build/hoverIsNotATap.mjs`, which moves every `:hover` selector (kit dist included) into `@media (hover: hover)` so tapped buttons do not stick in hover paint; copy it.

## 10. Keyboard

AttackFM never touches `window.visualViewport`. The keyboard is handled by `100dvh` roots, scroll containers that own their overflow (`.loginGate { position: fixed; inset: 0; overflow-y: auto }`), and focusing a field 180 ms after a sheet opens (`JoinGrooveSheet`). Android sets no `windowSoftInputMode`. Glyph's editor needs a bar pinned above the keyboard, which AttackFM has no precedent for; a `visualViewport` `resize`/`scroll` listener writing `--app-keyboard: calc(100dvh - visualViewport.height)px` is the obvious addition, verified on both webviews.
