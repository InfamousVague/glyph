The quickest way into the source is to follow one thing through it. Here are five, each from the tap to the wire, naming the file at every step. How the app is built says what each part is.

Sending a text

On an Android phone where Ghost Messaging is the texting app.

lib/ui/thread.dart: words alone to one friend go by the routes (the next section). Anything else is a text: Sms.instance.send.

lib/sms.dart passes send to Sms.calls. On Android that is the overlay (lib/standalone/overlay.dart), which passes a phone number on to the channel ghost_messaging/sms, answered in MainActivity.kt.

Sender.send in Messaging.kt. One person and no attachment is an SMS, sealed first by E2e.kt where encryption is on with them. Several people, or a picture, is an MMS, which Pdu.kt encodes.

Store.kt writes the message to Android's own database, and Android's SmsManager sends it. Reports of sent and delivered come back to SmsStatusReceiver.

Bus.changed sends an event up ghost_messaging/events; Sms.instance.changes fires and the thread and list read again.

A text arriving runs the other way: SmsDeliverReceiver in Messaging.kt writes it, Notifier.kt shows it, paired computers are told, and the screen hears the same event.

A message to a friend

Friends.sendText (lib/friends/friends.dart) stores the message where the person's texts are, so it is in the conversation whether or not it has gone.

An Envelope of kind text goes to Net.send (lib/net/net.dart), and on to Switchboard.send.

The switchboard (lib/net/switchboard.dart) seals the envelope with the key the two installs share, wraps it as a packet, and tries the routes in order. A message isn't allowed to cost money, so the SMS route is passed over and the hub is tried.

HubCarrier.send (lib/net/hub_carrier.dart) hands it to the relay's hub (relay/lib/hub.dart), which passes it to the friend's connected devices, or keeps it and says so.

Passed on, the sender waits a few seconds for the other app's answer and marks the message delivered. Kept, it is marked sent, and the friend's closed app is woken: an Android phone by an empty data text (at most one every ten minutes), an iPhone by a push from relay/lib/pushes.dart.

The packet arrives at Switchboard, which joins its parts, opens it, drops it if it has been seen before, and answers. Friends stores it, and the conversation changes.

Joining a call in a space

Voice.join (lib/voice/channels.dart) checks the hub is reachable and the circle's roles allow voice, and leaves any call already on.

RtcMedia (lib/voice/rtc.dart) opens it, with noise removal from native/voicefx in the capture path. On Android a foreground service (CallService.kt) keeps the call alive with the screen off.

VoiceSession.join (lib/voice/voice.dart) joins the space's room on the hub with the name and token made from the space's seed. The hub answers with who is there.

The newcomer makes a WebRTC connection to each member and says an offer in the room, sealed with the space's key. Each answers, and both sides exchange candidates the same way.

From there the call's sound and picture go between the members' devices. The hub carried the setup and carries none of the call.

Pairing a computer

PhoneLink.beginPairing (lib/desktop/link/link.dart) makes a key pair and 16 random bytes and draws them as a QR code.

Desk.begin (Desk.kt) makes its own key pair. Both ends now work out the same pairing key from the two key pairs and the code's random bytes (DeskCrypto, in Kotlin and in lib/desktop/link/crypto.dart).

Over the local network where the phone can be found there, otherwise through a ten-minute channel on the relay. Each connection starts with hellos in the clear, then keys of its own, then everything sealed (LinkSession, DeskSession.kt).

Both show six digits made from the pairing key. They match only if nobody is in the middle; the person confirms on both.

The computer's screens call Sms.instance as a phone's do. LinkCalls (lib/desktop/remote.dart) turns each call into a sealed request, DeskCalls in DeskSession.kt runs it on the phone, and the answer is kept sealed on the computer for next time.

Adding a Marketplace plugin

MarketState (lib/market/market_state.dart) reads the relay's catalog and its list of withdrawals.

For each entry the app checks the reviewer's signature against the keys it ships with (lib/plugins/pack/review_keys.dart), fetches the plugin's file, checks its SHA-256, and reads it (lib/plugins/pack/manifest.dart). The card is drawn from the checked file, never from what the catalog says of it.

addListing (lib/ui/market/market_flows.dart) shows what the plugin reads and adds, from the same file.

InstalledPlugins.installReviewed (lib/plugins/pack/installed.dart) checks it once more, keeps the file, and adds it to the registry as a PackPlugin. The list sorts itself again with the plugin's tags and tabs.

The approval is checked again and withdrawals applied, so a plugin withdrawn after it was added stops.
